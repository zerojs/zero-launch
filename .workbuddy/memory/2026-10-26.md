## 构建并运行 LaunchNext（2026-10-26 晚，用户要求"运行看效果"）
- 成功命令（前台 + 沙箱绕过审批）：

- 环境坑（全部已定位）：
  1. xcode-select 指向 CommandLineTools → 必须设 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`
  2. 沙箱拦截 xcodebuild 删除 `~/.swiftpm/security`（指向 ~/Library/org.swift.swiftpm/security 的符号链接）→ 需沙箱绕过；**后台任务拿不到绕过审批**（会直接以沙箱失败），必须前台跑
  3. 签名：pbxproj 写死 CODE_SIGN_IDENTITY="Apple Development" + DEVELOPMENT_TEAM=D4KD8XCCL6 + per-sdk 变体，本机无证书 → 命令行覆盖 ad-hoc 签名
  4. **不要**在命令行覆盖 per-sdk 变体：`"CODE_SIGN_IDENTITY[sdk=macosx*]"="-"` 会被 xcodebuild 按第一个 `=` 拆成键 `CODE_SIGN_IDENTITY[sdk` 值 `macosx*]=-`，报 "No certificate matching 'macosx*]=-'"
  5. 截图验证 UI 不可行：screencapture 被 TCC 拦（"could not create image from display"），沙箱绕过也没用
- 修复的真实源码 bug：CAFolderGridView.swift cleanupExternalDrag 里 `if let externalDragMonitor { NSEvent.removeMonitor(...); externalDragMonitor = nil }` —— Swift 简写遮蔽使块内 externalDragMonitor 变成不可变 `Any` 常量，赋值编译失败；把 `= nil` 移到 if-let 块外（已改，未提交）
- 产物：build/Build/Products/Debug/LaunchNext.app；LSUIElement 应用（无 Dock 图标），非登录项启动时窗口立即显示；数据落 ~/Library/Application Support/LaunchNext/Data.store

## 修复 dwell 接力拖拽 z-order bug（2026-10-26 晚，用户实测反馈）
- 用户反馈：拖拽悬停文件夹（投放目标）→ 文件夹展开后，文件夹内容层级高于被拖拽的 app，挡住 app
- 根因：CAFolderGridView.makeDraggingLayer 创建的拖拽层只靠 addSublayer 插入顺序置顶，未设 zPosition；主网格 CAGridView.createDraggingLayer 有 `container.zPosition = 1000`（第 490 行）——当初就是为同类问题加的。插入顺序在展开过渡/SwiftUI 宿主合成场景下不可靠
- 修复：CAFolderGridView.swift makeDraggingLayer 加 `container.zPosition = 1000`（内部拖拽 + 外部接力拖拽两条路径都走 makeDraggingLayer，一并覆盖）；已构建验证、重启应用
- 构建新坑（重要）：swift-plugin-server（SwiftData 宏展开）在内层 sandbox-exec 报 `sandbox_apply: Operation not permitted`，报错形如 "external macro implementation type 'SwiftDataMacros.PersistentModelMacro' could not be found ... malformed response"。前两次构建没触发是因为 FolderInfo.swift 的编译结果命中缓存。解法：xcodebuild 追加 `OTHER_SWIFT_FLAGS="-disable-sandbox"`
- 完整可用构建命令：
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project LaunchNext.xcodeproj -scheme LaunchNext -configuration Debug -derivedDataPath build build CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM="" CODE_SIGN_IDENTITY="-" OTHER_SWIFT_FLAGS="-disable-sandbox"`

## 真根因：clipShape 裁切（2026-10-26 深夜，stderr 日志实证）
- zPosition 修复后用户复测"范围内能看到、范围外看不到"——不是层级问题，是**裁切**
- 实证（lnDebugLog 写 FileHandle.standardError 无缓冲）：
  - 交接链路全部正常：handleFolderDwellFire → incoming 状态 → makeNSView → updateNSView 消费 → beginExternalDrag
  - 层序本来就对：rootLayer siblings = [contentLayer z=0 | draggingLayer z=1000]
  - 拖拽点大量在视图边界外：point=(-98.8, 316.5)，轨迹 x 到 -154、y 到 -90（bounds=(0,0,997,555)）
- 真凶：FolderView.swift folderContent 的 `.clipShape(RoundedRectangle(cornerRadius: 30))` 把溢出面板的拖拽层切掉
- 修复：删掉该 clipShape（玻璃圆角由 liquidGlass(in:) 提供；图标有 padding+contentInsets 内缩；VStack 中 folderContent 是后子视图，溢出层反而会盖在标题上方，符合"拖拽 app 层级最高"预期）
- 诊断日志手法沉淀：① GUI 应用 print 到重定向文件是块缓冲，SIGTERM 直接杀不刷盘（exit 143 日志全丢）→ 必须写 stderr；② 从终端直接跑 .app/Contents/MacOS/xxx 可捕获输出；③ 遗留生命周期日志（beginExternalDrag/cleanup 等）待用户确认修复后清除
