## 文件夹重命名输入框样式（延续 2026-10-26 会话）
- 用户诉求：点击改文件夹名时，文件名区域要有「输入框背景」；清空文件名后提示文案要「白色 + 半透明」，而不是当前的黑色
- 根因：`FolderView.swift` 的 `folderTitleSection` 用 `.textFieldStyle(.plain)`（无任何背景）；而 `TextField` 的 prompt 由 AppKit 渲染，颜色取自 `NSColor.placeholderTextColor`，SwiftUI 的 `.foregroundColor` 只作用于已输入文本、对 prompt 无效 → 浅色模式下 prompt 呈黑色，无法通过修饰符改色
- 修复（`LaunchNext/FolderView.swift`，`folderTitleSection` 编辑态分支）：
  1. `TextField(appStore.localized(.folderNamePlaceholder), ...)` → `TextField("", text: $folderName)`，prompt 置空，改由 `.overlay(alignment: .center)` 自绘占位文案，条件 `folderName.isEmpty`，样式 `.font(.title)` + `.foregroundColor(.white.opacity(0.45))` + `.allowsHitTesting(false)`
  2. 输入框背景：`.padding(.vertical, 6).padding(.horizontal, 14)` + `RoundedRectangle(cornerRadius: 12, style: .continuous).fill(Color.black.opacity(0.28))`，再叠一层 `strokeBorder(Color.white.opacity(0.22), lineWidth: 1)` 描边
  3. 编辑态文字统一 `.foregroundColor(.white)`（深色半透明底上保证对比度；非编辑态仍走 `AppStore.customIconLabelNSColor ?? .primary`）
  4. 关键坑：prompt 置空后 `TextField` 内在宽度会塌缩成窄条 → 必须补 `.frame(minWidth: 240)`，否则输入框变成一个很小的方块

## Bug：dwell 展开文件夹后取消拖拽，文件夹图标不回弹
- 复现：拖 app 悬停文件夹 → 2s 自动展开 → 继续按住拖到面板外 → 松手 → 文件夹面板关闭了，但主网格里该文件夹图标仍停在 1.3x 放大态
- 根因（`CAGridView+Input.swift`）：图标放大由 `applyScaleForIndex` 按 `dropTargetIndex == index` 算出来（`iconScale = 1.3`）。`cancelDragging()` 里只是 `dropTargetIndex = nil`，**没有重算该图标的缩放** → CALayer 上的 1.3x 变换残留。而 dwell 触发展开时 `handleFolderDwellFire` 正是调 `cancelDragging()`，所以必然复现。对照 `clearDropTargetHighlight()` 是有 `applyScaleForIndex(target, animated: true)` 的，这条路径漏了
- 修复：`cancelDragging()` 开头 `let previousDropTarget = dropTargetIndex`，置 nil 后补 `applyScaleForIndex(previousDropTarget, animated: true)`
- 排查结论（顺带确认无其他问题）：`updateReorderPreview(nil)` 会把 `currentHoverIndex` 置 nil，所以拖出面板外松手不会误落进文件夹；`finishExternalDrag` 的 `insideBounds` 判定正常走 `onExternalDragCancelled` → `openFolder = nil`
- 构建通过、应用已重启（PID 81073）

## 文件夹重命名交互两处修正（同日后续）
1. **编辑态点击外部不退出编辑**
   - 根因：`LaunchpadView.swift` 遮罩层 `Color.black.opacity(0.1)` 的 `onTapGesture` 是 `if !appStore.isFolderNameEditing { ... }` —— 编辑中直接整段跳过，什么都不做。点背板不会转移第一响应者，TextField 的 `@FocusState` 收不到失焦，所以 `FolderView` 里 `.onChange(of: isTextFieldFocused)` 那条兜底也不会触发
   - 修复：新增 `AppStore.folderNameEditCancelRequestID: String?`（沿用已有 `folderRenameRequestID` 的"请求-消费"模式）；遮罩 tap 时若在编辑 → 写入 `openFolder?.id` 并 `return`（本次点击不再关文件夹）；`FolderView.consumeNameEditCancelRequestIfNeeded()` 比对 `folder.id` 后调 `finishEditing()`
   - 语义选择：外部点击 = 提交式退出（与点击文件夹内部一致），不连文件夹一起关，避免"只想结束改名却被关掉整个文件夹"
   - 顺带：`finishEditing()` 补 `isTextFieldFocused = false` 主动交还焦点；`handleHeaderBackgroundTap()` 也纳入同一逻辑（顶栏同样算"外部"）
2. **输入框背景太长**
   - 上一版 `.frame(minWidth: 240)` 是拍脑袋值。改为按文本实测宽度自适应：`editNameBoxWidth` = `NSString.size(withAttributes:)[.font: NSFont.preferredFont(forTextStyle: .title1)]` + 28（左右 padding 各 14），夹在 [88, 340]
   - 为什么用 AppKit 同步测而不用 GeometryReader + PreferenceKey：后者要先渲染再回读，会有一帧宽度跳变（尤其是从 240 突然缩到实际宽度那种）
   - 实测校验：`preferredFont(forTextStyle: .title1)` = SFNS-Regular 22pt，2 个 CJK=41.9pt / 5 个 CJK=104.7pt，与 SwiftUI `.title`（macOS 下映射 title1）一致
   - 内容为空时按占位文案宽度算，避免空文本把框塌成窄条
- 构建通过、应用已重启（PID 87258）
