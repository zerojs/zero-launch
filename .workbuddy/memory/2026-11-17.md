## 拖拽两处一致性修复

### 1. 从文件夹拖出时显示黑色 app 名
- 根因：CA 渲染器自己的拖拽层（`CAGridView.createDraggingLayer` / `CAFolderGridView.makeDraggingLayer`）只画图标不带名字；
  但"文件夹拖出到主网格"的接力拖拽走的是 SwiftUI `DragPreviewItem`（`LaunchpadView:993-1001`，在 CA 分支的 ZStack 里），
  它的 `.app` 分支带 `Text(app.name)`，`.primary` 在浅色外观下是黑字 → 不一致。
- 修法：`DragPreviewItem` 增加 `showsLabel: Bool = true`，在 CA 分支调用处传 `false`；旧 SwiftUI 网格（`else` 分支 + `FolderView:355`）保持默认 true。

### 2. 第一次长按只抖动、拖不动，要按第二次
- 根因：`mouseDragged` 起拖条件是 `if !isDraggingItem, let idx = pressedIndex`，
  而长按进入抖动时 `handleLongPressForUninstall` 显式清掉了 pressedIndex（注释说是为了吞掉 mouseUp 防止启动 app）。
  清掉后同一次按住里的位移就没有据以起拖的下标。
- 修法（两个网格同改）：
  - `CAGridView+Uninstall.handleLongPressForUninstall`：删掉 `setPressedIndex(nil)`，改为 `enterJiggleMode(); isJiggleMode = true`
  - `CAFolderGridView.handleLongPressForUninstall(at:)`：删掉 `pressedIndex = nil; applyScale(...)`，改为 `isJiggleMode = true; onEnterJiggleMode?()`
  - 松手不误启动 app 由两处 `mouseUp` 里已有的 `isJiggleMode` 分支兜住（抖动模式下 app 不启动，文件夹仍可点开）
  - 本地 `isJiggleMode = true` 要**先**设置：updateNSView 回填要等下一次 SwiftUI 更新，同一轮事件里的 mouseUp 读不到
- 已验证：`rebuildLayers` 不会重置 pressedIndex，所以只删显式清零即可。

## 卸载 App 权限问题：改为四级兜底（22:42）
现象：系统设置「App 管理」里 ZeroLaunch 开关是**开的**，仍报 `你没有将文件"DeskWidgets"移入废纸篓的权限`。
已知：`/Applications/ZeroLaunch.app` 为 ad-hoc 签名（无 Team ID），每次 xcodebuild 后 CDHash 变化
（596c5b3e → 8c78f63d → 本次再次变化）；TCC 列表里还有 `LaunchNext_2.4.1_backup` 这类失效残留。
推断：授权记录存在（开关显示 ON），但绑定的二进制已不是当前运行的这个。

### 实现（AppStore.uninstallApp 四级降级）
1. `FileManager.trashItem` —— 需本进程「App 管理」授权
2. `moveBundleToTrashByRename` —— 纯 rename 到 `~/.Trash`，绕开"废纸篓"通道
3. `trashBundleViaFinder` —— NSAppleScript 让 Finder 代删，不消耗本 app 的 App 管理授权
4. `NSWorkspace.recycle` —— 最后再走 LaunchServices
每级都用 NSLog 记录，失败原因可查。

### 配套
- 新增 `LaunchNext/LaunchNext.entitlements`，声明 `com.apple.security.automation.apple-events`
  （Hardened Runtime 下发 Apple Event 必需，否则 -1743）
- pbxproj 注入 `CODE_SIGN_ENTITLEMENTS`（Debug/Release 各一处）
- 失败弹窗现在附带 `NSError` 的 domain + code，便于区分 TCC / POSIX / 其他

### 待验证
用户实测；若第 3 级被触发会弹「ZeroLaunch 想要控制访达」，必须点允许。

## 拖边缘翻页：只允许一个空白新页 + 未使用则回收（23:39）

### 根因
- `CAGridViewRepresentable:198` 的 `onRequestNewPage` 闭包**每次触发都无条件追加一整页** `.empty`；
- `startEdgeDragTimer` 翻页后 0.2s 又调 `checkEdgeDrag` 自检，指针仍停在边缘 → 再触发 → 再建页，页数无限增长；
- 且建页走 `DispatchQueue.main.async`，紧随其后的 `navigateToPage` 用的还是旧 `pageCount`，被钳回原页 →
  下一轮 +0.2s 自检才真正翻过去，表现为"到边缘要卡一拍才翻页"，同时也放大了重复建页。

### 修法
- `AppStore`：新增 `didCreatePageInDragSession` 会话闸门 + `requestNewPageForDragAtEdge()`（一次拖拽最多开一页）、
  `finishDragSession()`（`cleanupUnusedNewPage()` + `removeEmptyPages()` + `clampCurrentPageWithinBounds()`）；
  原先的 `createNewPageForDrag()`（带 `pendingNewPage` 记录）从死代码变成唯一建页入口。
- `CAGridView`：新增 `onDragSessionEnded` 回调；`endDragging` 尾部触发，`cancelDragging` 用
  `hadActiveDrag = draggingItem != nil` 判重后触发（避免拖拽已收尾时的重复调用误删页）。
- `CAGridView+Input.flipPageDuringEdgeDrag`：末页需要建页时先 `onRequestNewPage?()`，再
  `asyncAfter(0.05)` 才 navigate，让 SwiftUI 把新 items 回灌进网格；抽 `scheduleEdgeDragRecheck()`。
- `CAGridViewRepresentable`：`onRequestNewPage` 改为只调 `requestNewPageForDragAtEdge()`，
  并接上 `onDragSessionEnded → finishDragSession()`。

### 边缘提示条（此前一版被 23:26 的 file-rollback 抹掉，本次重建）
- 新增 `LaunchNext/EdgeHintController.swift`：贴边的 `CAGradientLayer` 白雾（靠边 0.30 → 0.10 → 0）
  + chevron + 圆角描边按 `progressDuration` 从 `strokeEnd 0→1` 走满即翻页；`zPosition 900`（高过角标、低于拖拽预览 1000）。
  同一侧持续停留**不重置**进度（`changed || animation(forKey:"fill") == nil` 才重放），否则永远走不满。
- 新增 `LaunchNext/CAGridView+EdgeHint.swift`：`updateEdgeHint(side:)` 薄封装。
- `CAGridView.swift` 加 `lazy var edgeHintController`（width = min(threshold+12, 72)）；
  `checkEdgeDrag` 里按左右边缘驱动，`cancelEdgeDragTimer()` / `cancelDragging()` 收起。
- `CAFolderGridView`：同样持有 controller（inset 48 / minHeight 120），两处重复的边缘块合并为
  `handleEdgeFlip(at:)` + `updateEdgeFlipHint(direction:)`（末页/首页/动画中不提示），`layout()` 里 `layoutIfVisible`。

### 遗留
- 若窗口在拖拽中途被销毁，`didCreatePageInDragSession` 可能残留 true，代价是下一轮拖拽少建一次页，再下一次自动恢复。
- 主网格翻页后进度条停在满格，未做"每次翻页重放进度"。

## 边缘提示条改为占「最外侧空白带」（次日 00:2x）

现象：提示条压在最后一列 app 图标上（截图里白色 app 图标与提示条叠在一起）。
真因：列宽是均分的（`cellWidth = (availableWidth - 总列间距) / columns`），图标在单元格内居中，
所以**最右侧空白带只有半个单元格减半个图标**。提示条原来固定 72pt，比这条带子宽，必然侵入图标区。

修法（`CAGridView+EdgeHint.swift`）：
- 新增 `trailingEdgeMargin()`：按 `columns / columnSpacing / iconSize / contentInsets` 反算
  `bounds.width - 最后一列图标右缘`（左右对称，同一套算法通用）；
- `updateEdgeHint` 里把宽度改成 `max(28, min(72, margin - 4))`，贴边摆放 → 只占空白带，不再压图标。
- 实测参数（1470pt 屏 / 7 列 / spacing 20）：单元格 192.9pt；图标 47pt 时空白带 ≈73pt（正好等于用户画的红框宽度），
  图标 116pt 时空白带只剩 ≈38pt → 条子自动收窄到 34pt，属预期。
- 竖向：主网格 `verticalInset` 88 → 44、`minHeight` 260（用户要的是近乎通栏的"导轨"）；文件夹面板 44pt 宽 / inset 32。

### 环境事实（复用价值高）- 屏幕逻辑分辨率 **1470×956 @2x**（`system_profiler` 报的 2560×1664 是物理/缩放值，以 `NSScreen.frame` 为准）
- 沙箱里 **`screencapture` 不可用**（could not create image from display，缺屏幕录制授权）→ 无法自查渲染结果
- 沙箱无 PyObjC；查窗口几何用 `swiftc` 编译一段 `CGWindowListCopyWindowInfo` + `NSScreen.screens` 的小程序即可

### 二轮微调（00:3x）
- 翻页停留从 0.4s → **0.8s**（`CAGridView.edgeDragDelay` / `CAFolderGridView.pageFlipDelay`），
  提示条进度动画绑同一个值；主网格持续贴边约 0.8+0.2=1.0s 翻一页，文件夹面板每次翻页后需移出 60pt 边带再进。
- 圆角 22 → **10**（`EdgeHintController.cornerRadius` 改为 var）。
- "提示条压住图标"的结构性问题：最外侧空白带只有半个单元格减半个图标（≈73pt），
  条子要变宽就必然压图标 → 反过来给网格加左右 gutter：
  `CAGridView.edgeGutterWidth = 26`，在 `CAGridViewRepresentable.effectiveContentInsets` 里
  加到 `contentInsets.left/right`，空白带变 ≈99pt，条宽取 `max(44, min(96, margin - 2))` = 96pt 仍不越线。
  - 注意：SwiftUI 侧 `LaunchpadView` 的 `columnWidth`/`indexAt` 不带这个 gutter，
    非 CA 渲染分支与接力拖拽的落点判断会有 ≤26pt 的偏差（可接受，若要严格一致需同步那边）。
